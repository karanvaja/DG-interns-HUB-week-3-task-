HANDS-ON TASKS:

1. Install Sysmon:
On your Windows VM, install Sysmon using the SwiftOnSecurity config file. This config is widely used in SOC environments to capture detailed endpoint telemetry.

1. Download Sysmon from the official Microsoft Sysinternals page and extract the ZIP to C:\Sysmon.
2. Download the SwiftOnSecurity config file:
   https://raw.githubusercontent.com/SwiftOnSecurity/sysmon-config/master/sysmonconfig-export.xml
   Save it into the C:\Sysmon folder.
3. Open an elevated Command Prompt and navigate to C:\Sysmon. Run:
   sysmon.exe -accepteula -i sysmonconfig-export.xml
4. Verify installation by opening Event Viewer and navigating to:
   Applications and Services Logs > Microsoft > Windows > Sysmon > Operational
5. Take a screenshot of the Sysmon Operational log showing events are being captured.

2. Make Events and Find Them:
Do the following actions and then find the matching Sysmon events in Event Viewer. Take screenshots of each event.

- Open PowerShell (Sysmon Event ID 1 - Process Create)
- Create a new user account (Sysmon Event ID 1 - Process Create)
- Check for network connections (Sysmon Event ID 3 - Network Connection)
- Create a text file (Sysmon Event ID 11 - File Create)

For each event, document:
- Event ID
- Timestamp
- Key fields (Image, CommandLine, User, SourceIp, DestinationIp, TargetFilename)
- Why this event matters to a SOC analyst

3. Explore Linux Auditing with auditd:
On your Ubuntu VM, install auditd and use ausearch to find your commands. Take screenshots of the audit log entries.

1. Install auditd:
   sudo apt-get install -y auditd
2. Start and enable the auditd service:
   sudo systemctl enable auditd --now
3. Verify the service is running:
   sudo systemctl status auditd
4. Run a command to audit:
   sudo apt install nano
5. Use ausearch to find that command in the audit log:
   sudo ausearch -k nano
   Or search by message type:
   sudo ausearch -m EXECVE -ts recent
6. Take a screenshot of the audit log entry showing your command.
7. Document what fields are available in the audit log (type, msg, exe, command, uid, gid, etc.) and why each is useful.

4. Set Up Snort:
Install Snort on your Ubuntu VM. Configure HOME_NET and EXTERNAL_NET. Write and test the following starter rules.

IMPORTANT: VirtualBox Ubuntu guests usually name the network interface enp0s3 (or similar), not eth0. Before running any Snort commands, check your interface name with:
   ip a
Substitute your actual interface name in all Snort commands below.

1. Update your package repository:
   sudo apt-get update
2. Install Snort and its default rules:
   sudo apt-get install -y snort snort-common snort-rules-default
3. Verify the installation:
   snort -V
   This should return version information.
4. Edit the Snort configuration file to set your network:
   sudo nano /etc/snort/snort.conf
   Set HOME_NET to your local subnet (e.g., 192.168.1.0/24) and EXTERNAL_NET to !$HOME_NET.
5. Open the local rules file:
   sudo nano /etc/snort/rules/local.rules
6. Add the following starter rules:

   alert icmp any any -> $HOME_NET any (msg:"ICMP Ping Detected"; sid:1000001; rev:1;)
   alert tcp any any -> $HOME_NET 22 (msg:"SSH Connection Attempt"; sid:1000002; rev:1;)
   alert tcp any any -> $HOME_NET 80 (msg:"HTTP Traffic"; sid:1000003; rev:1;)

7. Test your configuration:
   sudo snort -T -i <your-interface> -c /etc/snort/snort.conf
8. Start Snort in console mode:
   sudo snort -A console -q -c /etc/snort/snort.conf -i <your-interface>
9. Test with ping and curl from Kali or another VM. Take screenshots of your Snort alerts.

5. Advanced Snort Rule - Detect Nmap SYN Scan and Map to MITRE ATT&CK:
Write a Snort rule to detect an Nmap SYN scan and map it to MITRE ATT&CK T1046 (Network Service Discovery). Note that T1046 is now named "Network Service Discovery" in the ATT&CK framework.

Add the following rule to /etc/snort/rules/local.rules:

alert tcp $EXTERNAL_NET any -> $HOME_NET any (msg:"MITRE T1046 - Nmap SYN Port Scan Detected"; flags:S; threshold:type threshold, track by_src, count 20, seconds 1; classtype:attempted-recon; metadata:mitre_technique T1046; reference:url,attack.mitre.org/techniques/T1046/; sid:1000004; rev:1;)

Explanation:
- flags:S — matches TCP packets with only the SYN flag set (half-open scan signature).
- threshold:type threshold, track by_src, count 20, seconds 1 — alerts when 20 SYN packets from the same source occur in 1 second.
- classtype:attempted-recon — maps the rule to reconnaissance activity.
- metadata:mitre_technique T1046 — explicitly tags the rule with the MITRE technique ID.
- reference:url — provides a link to the official ATT&CK page for T1046.
- Run nmap -sS <target> from Kali and check Snort alerts. Take screenshots.

| EXECVE | auditd | Command execution | Auditing Linux commands |
| USER_LOGIN | auditd | User login | Tracking Linux authentication |

| 1000001 | Snort | ICMP Ping Detected | Detecting network reconnaissance |
