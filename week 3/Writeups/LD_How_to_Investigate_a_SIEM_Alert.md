## Key Concepts Learned

### 1. What is a SIEM and how does an alert work?
- **SIEM (Security Information and Event Management):** A tool that collects logs from many different sources (firewalls, endpoints, servers, cloud), correlates them, and generates alerts when something suspicious happens.
- **SIEM Alert:** A notification generated by the SIEM when a specific rule or correlation condition is met. It is the starting point of an investigation.
- **Alert Fatigue:** SOC analysts receive hundreds of alerts daily. Triage is required to separate the noise (False Positives) from real threats (True Positives).

### 2. The Alert Triage Process
When an alert pops up, the analyst must triage it quickly. The typical process includes:
- **Initial Review:** Look at the alert name, severity, timestamp, and the assets involved (source IP, destination IP, hostname).
- **Context Gathering:** Pivot into the logs to see what happened around the same time. (e.g., Did a user login before a suspicious process ran?)
- **Threat Intelligence (TI) Check:** Run the IPs, domains, or file hashes through platforms like VirusTotal or AbuseIPDB to see if they are known malicious.
- **Decision:** Determine if the alert is a **False Positive** (benign activity) or a **True Positive** (malicious activity).

### 3. Investigation Methodology (The "Who, What, When, Where, How")
- **Who:** Which user account was involved? (Check user identity, privilege level, and recent activity).
- **What:** What exactly happened? (e.g., A process created a network connection, or a file was dropped).
- **When:** At what time did it happen? Is it outside normal working hours?
- **Where:** Which host or network segment is affected? (Is it a critical server or a normal workstation?).
- **How:** How did the attacker get in or how did the process execute? (Look at parent-child process relationships).

### 4. False Positive vs. True Positive
- **False Positive (FP):** The alert triggered, but the activity is legitimate (e.g., an IT admin running a vulnerability scan triggered a "port scan" alert).
- **True Positive (TP):** The alert triggered, and it is genuinely malicious (e.g., a user clicking a phishing link that ran a PowerShell payload).
- **Benign True Positive:** The alert is technically accurate (an action happened), but it doesn't represent a threat (e.g., a user successfully logging in from a new location with MFA).

### 5. Threat Mitigation and Incident Response
Once a True Positive is confirmed, the SOC analyst must act:
- **Containment:** Isolate the affected endpoint from the network to stop the spread.
- **Eradication:** Remove the malware or block the malicious IP/domain at the firewall.
- **Recovery:** Restore systems to normal operation.
- **Escalation:** If the incident is severe, escalate it to Tier 2 / Tier 3 analysts or the Incident Response (IR) team.

## Personal Notes / Reflections
- **Context is King:** I realized that looking at an alert in isolation is dangerous. You must look at the surrounding logs (e.g., Sysmon Event ID 1 alongside a firewall log) to understand the full story.
- **The importance of Threat Intel:** Using tools like VirusTotal is a game-changer. It quickly tells you if an IP is part of a known botnet, saving a lot of manual analysis time.
- **Documentation:** Properly documenting every step—even for a false positive—is crucial. It helps in creating better detection rules in the future and proves compliance.
